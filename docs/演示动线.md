# 现场演示动线

> 两种节奏：**3 分钟极速版**（时间紧、只给人看个印象）和 **8 分钟标准版**（对应参赛视频）。
> 每一页都写清了「停多久 / 点什么 / 说什么 / 看点在哪」，照着走不会漏。

## 〇、演示前 5 分钟准备（务必做）

```bash
# 1. 重置演示数据（让数据从"干净起点"开始，避免上次演示留下的痕迹）
cd C:\Users\李嘉鑫\Desktop\传智杯
npm run reset:db

# 2. 启动（或直接双击桌面「启动智练SmartFit」）
npm run dev
```

- [ ] 浏览器打开 `http://127.0.0.1:5173`，用 **demo / 123456** 登录一次，确认能进
- [ ] **看一眼左下角状态**：必须是「**大模型已接入**」+ 模型 `deepseek-chat`
      （若显示"离线知识库模式"，说明 `server/.env` 里 `AI_API_KEY` 没生效，检查后重启）
- [ ] 浏览器缩放调到 **100%**（Ctrl+0），窗口最大化，关掉其他标签页
- [ ] 录屏时用 1600×1000 以上窗口；页面按 1600 宽度设计，太窄会换行
- [ ] 提前把「AI 计划」页打开一次预热（第一次生成页面资源加载慢），但**不要点生成**
- [ ] 手机静音、微信/QQ 关闭弹窗

> ⚠️ 生成计划约 **7 秒**、AI 教练首字约 **0.7 秒**、配餐约 **4 秒**。演示时说"稍等几秒它在思考"，不要急着乱点。

## 二、8 分钟标准版（10 个页面全覆盖）

### 1️⃣ 数据总览（约 50 秒）
- **操作**：登录后停留，鼠标依次划过四张指标卡
- **说什么**：
  - 四张卡：今日运动消耗 / 饮食摄入 / 运动时长 / 当前体重（体重带 ↓0.1kg 环比）
  - 「下面是今日目标完成度，四条进度条自动算的。」
  - 「右下角这三条建议不是写死的文案，是按我当前数据现算的——它知道我每天蛋白目标 180g、燃脂心率区间是 117~137。」
- **看点**：AI 智能建议卡右上角的「规则引擎 · 实时」标签

### 2️⃣ 运动打卡（约 60 秒）
- **操作**：选「徒手深蹲」→ 时长改 30 分钟 → 点「完成打卡」
- **说什么**：「打卡不是随便填数字。你选了深蹲，系统自动带出这个动作的 MET 值，用 `MET × 体重 × 时长 × 强度系数` 在后端算热量，返回给我的是 157 kcal 这样的结果——**健康数据必须可追溯**。」
- **滚动到下方**：「这是打卡日历热力图，GitHub 贡献图那种，一眼看出这个月坚持得怎么样。」
- **看点**：表单下方的「预计消耗」

### 3️⃣ AI 健身计划（约 2 分钟，**全场重点**）
**操作顺序**（不要乱）：
1. 目标选「减脂」、每周 4 天、4 周、45 分钟、新手、器械选「徒手+哑铃」、**伤病勾「膝关节不适」**
2. 补充说明填一句：「想重点练臀腿，不喜欢跑步」
3. 点「生成我的专属计划」→ **等 7 秒**（可以说"它在思考"）

**分三层讲**：
- **第一层（生成过程面板）**：
  「大模型生成阶段花了 6983 毫秒，用的是 deepseek-chat；然后是结构校验——这里显示『自动修复 0 处，按渐进超负荷规则由第 1 周展开至 4 周』；最后是安全审核通过。下面这一排是它**实际引用**的知识库条目：渐进超负荷原则、零基础新手的 4 周进阶路径、关节不适人群的替代动作……」
- **第二层（这里必须讲的加分点）**：
  「为什么只显示"由第 1 周展开"？因为我们**只让模型生成第 1 周的模板**，后 3 周由程序按渐进超负荷规则展开。原因很实在：如果让模型一次输出 4 周、70 多个动作项的 JSON，就会超出输出上限被截断、解析失败、整条链路降级——我们**实测过，耗时 19 秒最后还是退回规则引擎**。改成"模板 + 规则展开"之后，7 秒就一次通过。**让模型做决策，让代码做重复劳动。**」
- **第三层（安全与闭环）**：
  「因为勾了膝关节不适，你看腿部动作全是低冲击的，深蹲跳跃类没了。现在勾选一个动作完成——注意它**自动生成了一条运动打卡**，计划和打卡是打通的。」

### 4️⃣ 身体数据（约 50 秒）
- **操作**：停留 + 滚到代谢指标
- **说什么**：
  - 「六维健康雷达：BMI、体脂、肌肉量、腰围、静息心率、睡眠，每项都映射到理想区间换成分数。」
  - 「下面这排是最关键的：BMR 1743、TDEE 2702、目标热量 2252、蛋白 180g——**这些数字全部由代码算出来，不是模型算的**。算好之后才塞进提示词，从根上杜绝了大模型算错数。」
- **看点**：「体重/体脂双轴趋势」——体重降、体脂也降，但肌肉量在涨（这是良性减脂）

### 5️⃣ 数据可视化（约 40 秒）
- **操作**：点「近 30 天」→ 依次划过 6 张图
- **说什么**：「7/30/90 天可切。仪表盘是本周完成度，雷达图是训练部位均衡度（防止只练胸不练腿），下面是热量收支、训练量、身体成分和打卡热力图。」
- **看点**：雷达图——如果只有"力量"一个角凸出，就说明训练不均衡

### 6️⃣ AI 健身教练（约 1 分 30 秒，**第二重点**）
- **操作**：点推荐问题「我想减脂，但膝盖有旧伤，怎么安排训练？」→ 等流式输出（约 3 秒）
- **说什么**：
  - 「**第一，它是流式的**，一个字一个字往外蹦，首字 0.7 秒。如果等十几秒一次性弹出来，用户早关了。」
  - 「**第二，看下面这些标签**——引用了"关节不适人群的替代动作""减脂热量缺口设置""大体重人群减脂运动建议"，这些来自本地知识库，不是模型编的，可以点开验证。」
  - 「**第三，也是最重要的，看右边**：这一段是我注入给模型的"数据快照"——身体数据、目标、近 7 天打卡、今日饮食、当前计划进度全在里面。所以它说的不是通用建议，是"我这 60 天减了 3.3kg、今天蛋白还差 53g"。"
- **看点**：右侧「注入给 AI 的数据快照」这块面板（评委最爱问"你怎么保证不是瞎编"）

### 7️⃣ 健康饮食（约 60 秒）
- **操作**：点「生成配餐」→ 等 4 秒
- **说什么**：
  - 「目标热量 2255，AI 给了一日三餐加加餐。注意这几个标签：合计 2241 kcal、**与目标偏差 −0.6%（达标）**。」
  - 「这里有个工程细节：模型第一次给的份量偏小，**只配到 1373 kcal，偏差 −39%**。所以我们加了一道**份量自动校正**——以食物库为准按比例缩放每份克数再重算，你看到的『🔧 份量已自动校正』就是它干的活。**模型可以犯错，但产品不能交付错的方案。**」
  - 「满意就点『一键采纳』，直接写进今天的饮食记录。」
- **看点**：三大营养素供能比环图 + 推荐区间对比

### 8️⃣ AI 拍照识热量（约 60 秒，**多模态亮点**）
- **操作**：拖一张饭菜照片进上传区（手机端点「拍照」）→ 等约 2 秒
- **说什么**：
  - 「这是多模态能力：一张照片，模型识别出这一餐有面条、牛肉块、青豆、葱花和面汤，并估算每种的克数。」
  - 「**重点看每一项后面的标签**：牛肉显示『库内精确』——匹配到了食物库的『瘦牛肉（熟）』，热量用库里每 100g 数据算的；面条、面汤显示『模型估算』——库未收录才用模型值。**两种来源明确标注，不混在一起骗你。**」
  - 「还有个我们踩过的坑：早期版本把『面汤 300g』错配成『意面』，算出 474 千卡（真实约 30），整餐从 489 虚高到 917。现在加了**双源交叉校验**——库值与估算相差超 3 倍就判误匹配、弃用库值。你看到的是修正后的 489 千卡。」
  - 「**第二个坑更有意思**：拍一杯『迷你碗仔面（海鲜风味）』，检索居然把它配到『风味酸奶』——两者唯一的共同点就是『风味』这两个字。数字上拦得住（酸奶 25 千卡 vs 实际 150 千卡，差 6 倍，被规则弃用），但界面上顶着个『候选：风味酸奶』，用户会以为我在乱认食物。所以匹配层又加了**泛化词剔除 + 字符重叠率 ≥ 0.4**：口味、包装类词（风味/原味/迷你/袋装/无糖）不算相似依据，现在它老实显示『库未收录，采用 AI 估算值』。**这也说明为什么不能只靠分数阈值——词法相似不等于食物相似。**」
  - 「**有人会问：一张照片怎么知道重量？** 这是图像热量估算最难的地方。做法是先找尺度参照物——这里它找到了筷子（标准 25cm），据此推算碗口约 18cm，再用体积×密度换算。所以它给的不是一个假精确的数字，而是『200g，区间 150~250g，依据是筷子长度，可信度高』。照片里没有参照物时，它会诚实地把可信度降为低并提醒你。」
  - 「觉得份量不对？点『小份 150g』『大份 250g』一键校准，热量立刻重算——**把最终判断权交回给人**。」
  - 「**如果家里有厨房秤，这里最快**：称一下整盘 500g，输进这个框点『按总重校准』，系统按识别出的各食材比例自动分配——合计精确 500g、热量从 459 变成 397。**只知道一种食材也行**：把米饭改成实际 150g，点『按此推算全部』，其余按同一比例修正。」
  - 「份量可以改、热量实时重算；选餐次点『加入午餐』直接写进饮食记录。下面是识别历史，可回看、可稍后再记。」
  - 「**再往下是最实用的部分**：填克数看热量。我把面条改成 150g，热量立刻从 280 掉到 210。点『AI 分析这一餐』——它结合我的体重 75.2kg、BMI 23.7、减脂目标和今天已吃的 1439 kcal，告诉我这一餐只占今日目标 20%（午餐建议 30~42%）、蛋白只有目标的 14%、没蔬菜，然后给出具体建议：加 100g 熟牛肉把蛋白提到 45g、加 150g 西兰花、面条减到 150g。」
  - 「注意：**占比区间是代码按膳食指南判的，不是模型凭感觉说的**；模型只负责把结论说成人话并给出可执行的克数建议。」
- **看点**：数据来源标签（库内精确 / 模型估算）+ 双源冲突拦截 + 份量试算的实时重算 + AI 建议里引用用户真实数字

### 9️⃣ 运动社区（约 40 秒）

- **说什么**：「发帖可以关联打卡，关联后帖子会自动带出这张运动数据卡片——这是健康社区和普通论坛的区别。排序用的是『点赞×3 + 评论×5 + 时间衰减』，新内容有加成，不会让旧帖长期霸榜。右边是本周排行榜。」

### 🔟 个人中心（约 40 秒，**收尾**）

## 三、演示时可能被问的问题（照着答）

| 问题 | 一句话回答 |
|---|---|
| 「大模型是套壳吗？」 | 不是。计划是结构化 JSON 落库、能勾选能统计；生成过程六阶段可见；输出必须过白名单校验和安全审核才能入库。 |
| 「模型会不会瞎编动作？」 | 不会。提示词给动作白名单，校验阶段拿 exerciseId 跟数据库比对，编造的直接丢弃并计入修复数。 |
| 「没有网/没有 Key 怎么办？」 | 三层降级：大模型 → 修复重试 → 本地规则引擎/检索式问答。功能完整可用，界面会诚实标注当前模式。 |
| 「为什么不用向量数据库？」 | 知识库 166 条，BM25 + 结构化过滤已够用，且零依赖、毫秒级、可解释。BM25Index 是独立类，换 embedding 只改一处。 |
| 「为什么只生成一周？」 | 4 周 JSON 超出输出上限会被截断（实测 19s 后降级）。改成"模板 + 规则展开"后 7s 一次通过。这是主动的工程取舍。 |
| 「数据存哪？」 | SQLite 单文件，Node 内置驱动，零安装。数据访问收敛在 `db/index.js` 四个方法，迁 MySQL 只改一层。 |
| 「AI 建议能当医疗建议吗？」 | 不能，也不做。系统明确不诊断、不推荐药物，遇胸痛/晕厥/关节剧痛会提示就医；带伤人群自动回避禁忌动作。 |

## 四、万一出问题（现场救急）

| 现象 | 处理 |
|---|---|
| 页面打不开 | 地址用 `http://127.0.0.1:5173`，**别用 localhost**（可能走 IPv6 连不上） |
| 生成计划卡住超过 30 秒 | 网络抖动。刷新页面重试；实在不行直接讲"这次降级到本地规则引擎也照样出完整计划"（这本身就是亮点） |

| 端口被占用 | 双击桌面「启动智练SmartFit」，它会检测到已在运行并直接打开浏览器 |
| 想看日志 | `logs\launcher.log` |

## 六、📷 手机实拍演示（强烈建议加进视频，约 40 秒）

这是本作品**最容易被记住的一段**，因为它把"AI 原生"落到了最日常的动作上：掏出手机拍一张饭菜照片。

### 演示步骤
1. **电脑上**打开「健康饮食」页（`http://127.0.0.1:5173/diet`）
2. **手机上**打开 `http://<电脑IP>:5173`（同一 Wi-Fi；启动日志里有该地址，例如 `http://10.62.147.193:5173`）
3. 登录后进「健康饮食」→ 点 **「📷 拍照识别食物热量」** → **拍照**（会直接调用后置摄像头）
4. 对着饭菜拍一张 → 页面自动上传并识别（2~3 秒）
5. 结果区会列出：识别到的每种食材 + 是否匹配食物库 + 份量（可改）+ 该项热量
6. 选好餐次 → 点「加入午餐」→ 今日热量立刻更新

### 讲解词（照读）
> 「录饮食最烦的是什么？是搜食物、猜克数。所以我们做了拍照识别——
> 手机拍一张，AI 识别出这碗沙拉里有鸡胸肉、鹌鹑蛋、玉米粒、毛豆、紫甘蓝、圣女果、黄瓜、生菜 8 种食材，
> 而且给出了每种的份量估算。
> 但这里有个坑：模型说的是"香煎鸡胸肉"，我们食物库里叫"鸡胸肉（熟）"，怎么对上？
> 我们用了 **BM25 + 名称相似度双阈值**：只有字面得分够高、且去掉烹饪修饰后字符重叠率超过 60% 才算匹配。
> 最初只用 BM25 时，紫甘蓝被错配成紫薯、圣女果被错配成苹果——就是因为只共享一个"紫"字、"果"字。
> 匹配成功后，热量一律**用食物库的权威数据重算**，不采信模型估算值，保证和手动录入的口径完全一致。
> 你还可以自己改选食物、改克数，然后一键加入午餐。」
