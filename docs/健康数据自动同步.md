# 健康数据「自动同步」—— 不用导出、不用转 CSV、不用手动上传

> 对应页面：**设备同步 → ④ 自动同步**
> 相关代码：`server/src/modules/sync/routes.js`、`server/src/middleware/syncAuth.js`、`tools/health-sync.mjs`、`tools/lib/apple-health.mjs`

---

## 1. 先说清楚：为什么「网页自己去拉」做不到

| 想法 | 现实 |
| --- | --- |
| 网页直接读 Apple 健康 / HealthKit | ❌ Apple 从未给浏览器开放 HealthKit，Safari 与 iOS 上所有浏览器都一样 |
| 网页直连 Apple Watch | ❌ Apple Watch 不广播蓝牙标准心率服务（0x180D），只和 iPhone 私有通信 |
| 调华为运动健康 / 小米运动 / Zepp 云 API | ❌ 需要企业资质 + OAuth 审核，个人/校园项目拿不到 |
| Android Health Connect | ❌ 没有 Web 接口，只能由装了 App 的一方读 |

所以"自动"只能反过来做：**让能拿到数据的那一端，主动把数据推到平台**。
本项目为此提供「同步令牌 + 推送接口」，并用三条最省事的接法把它用起来：

| 通道 | 谁在推 | 需要装 App 吗 | 需要电脑开着吗 | 适合场景 |
| --- | --- | --- | --- | --- |
| **A. iPhone 快捷指令** | 系统自带「快捷指令」每天定时 | ❌ 不需要（快捷指令是 iOS 内置） | ❌ 不需要 | 最常见：iPhone / Apple Watch 用户 |
| **B. 电脑监听脚本** | `tools/health-sync.mjs` | ❌ 不需要 | ✅ 需要 | 电脑常开，或想直接吃「健康」导出 zip |
| **C. 安卓 HTTP Shortcuts** | 免费 App 定时发请求 | ✅ 需要 | ❌ 不需要 | 安卓 + 想定时自动 |

> 三条通道都用**同一枚令牌 + 同一个接口**，落库口径完全一致。

---

## 2. 生成令牌（只需一次）

1. 打开「设备同步」页，滚到 **④ 自动同步**；
2. 填个名字（例如「iPhone 快捷指令」），点 **生成令牌**；
3. **立刻复制** `sft_` 开头的字符串——明文只显示这一次。

安全设计（可讲）：服务端只保存 `SHA-256(令牌)`，不存明文；令牌只能推送健康数据，
不能读社交内容、不能改资料；页面上能看到「用过几次、最近什么时候用过」，可疑就一键撤销。

## 3. 通道 A：iPhone 快捷指令（推荐）

### 3.1 先验证链路

复制页面上的**一次性验证地址**（形如下面这样，已带上你的令牌），在 iPhone Safari 里打开：

```
https://<你的域名>/api/sync/push?token=sft_xxxx&steps=8600&restingHr=64&sleepHours=7.2
```

返回 `{"code":0,"message":"自动同步 1 天…"}` 就说明令牌和网络都通了。

### 3.2 做成每天自动跑

1. iPhone 打开「**快捷指令**」→ 底部「**自动化**」→ 右上「+」→「创建个人自动化」；
2. 触发条件选「**时间**」→ 每天 **22:00**（也可以选「App 关闭时 → 健康」）；
3. 添加操作「**获取健康样本**」：类型选「步数」，时间范围「今天」；
   再各加一条，类型分别选「静息心率」「睡眠」（睡眠选「睡眠分析」）；
4. 再加操作「**获取 URL 内容**」，URL 填上面那条地址——把里面的
   `8600` / `64` / `7.2` 换成前面三个操作的变量（URL 输入框里点「插入变量」）；
   方法保持 **GET**；
5. 下一步后**关闭「运行前询问」**（不关的话每天还得手点一下，就不算自动了），保存。

### 3.3 常见坑

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 打开返回 `401 同步令牌无效或已被撤销` | 令牌复制多了空格 / 已被撤销 | 重新复制或重新生成 |
| 返回 `400 没有可用数据` | URL 里一个数值都没带 | 确认至少带一个 `steps` / `restingHr` / `sleepHours` |
| 数据总是记到昨天 | 快捷指令在 0 点后跑，而变量取的是「昨天」的健康样本 | 加一个 `date=今天` 参数，或把定时改到当天 23:00 前 |
| 每天都要点一下才跑 | 自动化里「运行前询问」没关 | 编辑自动化 → 关闭「运行前询问」 |
| 想把一周历史一次补上 | GET 只支持单日 | 改用 `POST /api/sync/push` + `rows` 数组 |

## 4. 通道 B：电脑监听脚本（彻底告别"转 CSV 再上传"）

脚本：`tools/health-sync.mjs`（零依赖，Node 22+ 即可）。

### 4.1 一次性推送（替代旧流程）

```powershell
# 旧流程：导出 zip → node tools/apple-health-to-csv.mjs → 网页选文件上传（3 步人工）
# 新流程：一条命令（本机流式解析，只把聚合后的每日指标推上去）
node tools/health-sync.mjs --once "导出.zip" --url https://smartfit-qsyh.onrender.com --token sft_xxxx
```

支持的文件：Apple「健康」导出的 **zip**、解压后的 **export.xml**、手环导出的 **CSV / JSON**。

### 4.2 后台自动（无人值守）

1. 建一个目录，例如 `%USERPROFILE%\iCloudDrive\智练同步`（iCloud 云盘会和 iPhone 同步）；
2. iPhone 快捷指令里加一个「**存储文件**」动作，把每天的数据写成 CSV 存进这个目录
   （或把「健康」导出的 zip 直接存进去——iPhone 上「导出所有健康数据」后可以选存到 iCloud 云盘）；
3. 电脑上运行（也可双击根目录的 `启动健康数据自动同步.bat`）：

```powershell
node tools/health-sync.mjs --watch "%USERPROFILE%\iCloudDrive\智练同步" --url https://smartfit-qsyh.onrender.com --token sft_xxxx
```

行为说明：

- 启动先把目录里已有文件扫一遍（历史文件能补推）；
- 之后每 3 秒扫一次（iCloud / 网盘目录用 `fs.watch` 容易丢事件，轮询更可靠）；
- 已推过的文件记在 `tools/.health-sync-state.json`（大小 + 修改时间），**不会重复推**；
  文件内容变了会自动再推一次（同一天的数据是"更新"而不是"新增"，不会堆重复记录）；
- iCloud 还没下载完的 `.xxx.icloud` 占位文件会自动跳过，等落地后再推；
- 网络失败会重试 3 次，仍失败就留到下一轮继续。

### 4.3 参数表

| 参数 | 说明 |
| --- | --- |
| `--once <文件>` | 推送一个文件后退出 |
| `--watch <目录>` | 监听目录，长期运行（Ctrl+C 退出） |
| `--force` | 配合 `--watch`：已推过的文件也重推一次 |
| `--url <地址>` | 平台地址，默认 `http://127.0.0.1:3000` |
| `--token <令牌>` | 同步令牌；也可用环境变量 `SMARTFIT_SYNC_TOKEN`，或写在 `tools/.sync-config.json` |
| `--device <名称>` | 同步历史里显示的来源名 |
| `--dry-run` | 只打印将推送的内容，不上传 |
| `--reset-state` | 清空「已推送文件」记录 |
| `--interval <毫秒>` | 扫描间隔，默认 3000 |

配置文件写法（省得每次带参数，**该文件已在 .gitignore 里，不会进仓库**）：

```json
{ "url": "https://smartfit-qsyh.onrender.com", "token": "sft_xxxx", "device": "笔记本电脑" }
```

## 5. 通道 C：安卓

- **实时心率**：用 Chrome / Edge 打开 https 域名下的「设备同步」页走 ①，首次会申请「附近的设备」权限；
- **定时推送**：装免费的「HTTP Shortcuts」（或 MacroDroid / Tasker），向
  `https://<域名>/api/sync/push` 发请求，请求头加 `X-Sync-Token: sft_xxxx`，
  参数带 `steps` / `restingHr` / `sleepHours`，设置每天定时执行。
- 小米/华为手环记得先在自家 App 里开启「心率广播」，否则蓝牙搜不到。

## 6. 数据落库口径（三个通道完全一致）

| 数据 | 落到哪 | 说明 |
| --- | --- | --- |
| 体重 / 静息心率 / 睡眠 | `body_records` | 一天一条，已存在就**更新**不新增 |
| 步数 | `workout_logs`（日常步行） | 时长 = 步数 ÷ 100；热量 = MET 3.5 × 体重 × 时长；同一天只保留一条设备来源打卡 |
| 同步记录 | `device_syncs`（`source='auto'`） | 同步历史标记为「自动同步」，与导入/演示区分开 |

接口（幂等，重复推送安全）：

```
POST /api/sync/push          请求头 X-Sync-Token
{
  "device": "iPhone 快捷指令",
  "date": "2026-10-22",                                  // 可省略，默认今天
  "metrics": { "steps": 8600, "restingHr": 64, "sleepHours": 7.2, "weightKg": 75.2 },
  "rows":    [ { "date": "2026-10-20", "steps": 8300 } ],  // 可选，一次补多天
  "heartRate": { "avg": 78, "max": 132, "min": 58, "durationSec": 1800, "saveAsRestingHr": false },
  "dryRun": false
}

GET  /api/sync/push?token=sft_xxxx&steps=8600&restingHr=64&sleepHours=7.2   // 快捷指令最省事的用法
GET  /api/sync/ping                                                        // 校验令牌
```

其他接口（需要登录态，供页面使用）：`POST /api/sync/tokens` 生成、`GET /api/sync/tokens` 列表、
`DELETE /api/sync/tokens/:id` 撤销、`GET /api/sync/setup` 返回推送地址与模板。

## 7. 排错

| 现象 | 排查 |
| --- | --- |
| `401 缺少同步令牌` | 请求头写成 `X-Sync-Token`（或 URL 带 `?token=`） |
| `401 令牌无效或已被撤销` | 在页面上重新生成；注意不要带入多余空格 |
| `400 没有可用数据` | 至少带一个指标；`rows` 里每行必须有 `date` |
| 脚本报 `fetch failed` / `ECONNREFUSED` | 检查 `--url`；本地要先把后端跑起来（双击「启动智练SmartFit」） |
| 线上推送很慢或第一次失败 | Render 免费实例休眠，首次唤醒 30~60 秒，重试即可（脚本会自动重试 3 次） |
| 线上新推的数据过一会没了 | Render 免费实例容器是临时盘，重启会重建。要长期保留：加 Persistent Disk，并把 `DB_FILE` 指到挂载路径（见 `docs/部署到云-永久地址.md`） |
